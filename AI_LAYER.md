# Этап 5 — аналитический слой: первая итерация

Статус всего этапа: In Progress. Реализован фундамент классификации/приоритетов
и подготовлена выключенная интеграция OpenAI. Модель и бюджет пока не согласованы;
живых запросов к модели и измерения её качества не было.

## Доступно без внешней модели

- Категории: сведения об утечках, публичные профили, аватары и косвенные признаки
  регистрации. Ошибки/отсутствие/пропуски учитываются в покрытии, не как угрозы.
- Группировка повторных наблюдений одного источника и аккаунта. Повторные записи
  утечки одного провайдера с одинаковыми именем/датой/областью категорий объединены
  для сводки; разные провайдеры/даты не склеиваются. Исходные проверки не меняются.
- Приоритеты: «В первую очередь», «Требует проверки», «Для сведения», «Исключено
  по вашей отметке». Это объяснимые правила, не вероятность взлома/принадлежности.
- Категория паролей в конкретной записи — повод в первую очередь проверить защиту,
  не доказательство раскрытия действующего пароля. Общие категории LeakCheck не
  приписываются конкретной утечке. Противоречия требуют проверки, а не уверенного вывода.
- «Не моё» исключает персональный приоритет, не удаляя факт источника; отмена отметки
  восстанавливает приоритет. «Моё» не становится независимым доказательством.
- В PDF появился блок приоритетов. Новые карточки этапа 4 сохраняют минимальную
  основу анализа внутри существующего шифрованного snapshot. PDF карточки
  пересчитывает приоритеты после отметок без новых внешних запросов.

Числовой персональный risk score и семантическое объединение похожих названий
не применяются: пока нет размеченной выборки для калибровки.

## Подготовленная роль OpenAI

OpenAI выбирает максимум пять существующих fact_ids для сводки. В этой итерации
свободный сгенерированный текст не публикуется. Подписи/объяснения строятся из
проверенных шаблонов, а не из ответа модели. Неизвестные IDs, дубли, лишние поля,
пропуск первых пяти высокоприоритетных фактов, изменение порядка приоритетов,
незавершённый ответ и отказы отклоняются. Ранее сохранённая подборка снова
проверяется после отметок пользователя; устаревшая подборка заменяется правилами.

В запрос допускаются только категории/перечисления, число записей и агрегаты:
нет email/телефона/username, URL, названий утечек, имён, свободных пояснений
источников, временных меток и идентификаторов пользователя/задания. Хеши персональных
идентификаторов также не передаются. Данные всё ещё описывают находки о безопасности,
поэтому их передачу и уведомление пользователей нужно согласовать до включения.

API: фиксированный POST https://api.openai.com/v1/responses, без redirects,
инструментов, истории conversations и повторов. JSON schema strict; store=false.
Это отключает сохранение Response-состояния, а не обещает отсутствие любого
хранения провайдером. Полные ответы/запросы/ключи не логируются и не сохраняются.
Сохраняются только принятые fact_ids и статус подборки внутри шифрования карточки.

Официальные ссылки (проверены 29 октября 2026):
- https://developers.openai.com/api/docs/guides/structured-outputs
- https://developers.openai.com/api/docs/guides/migrate-to-responses

## Настройки — по умолчанию выключено

```
AI_SUMMARY_ENABLED=false
AI_DATA_TRANSFER_APPROVED=false
OPENAI_API_KEY=
AI_SUMMARY_MODEL=
AI_MAX_CALLS_PER_HOUR=0
```

Для включения потребуются согласованные провайдер/модель/бюджет, ключ в Render
secret storage и подтверждение правил передачи данных/уведомления пользователей.
Переменные в рабочем Render в этой итерации не меняются. Не вставлять ключ в чат,
PR, исходники или отчёт. Подготовка кода не подтверждает доступ к API/модели.

Явный лимит 1–1000 попыток за часовое окно хранится в общей PostgreSQL-таблице
лимитов, не сбрасывается от рестарта процесса; неудачи тоже расходуют квоту.
Это ограничение запросов, не денежный потолок. Денежный бюджет и доступные
ограничения провайдера нужно согласовать отдельно с учётом выбранной модели.
На запрос: до 16 KiB JSON входа и 512 выходных токенов, до 64 KiB ответа;
таймаут соединения 3 секунды/чтения 8 секунд, проверка срока обработки тела 12 секунд
между чтениями. Это не жёсткий общий 12-секундный deadline сетевой операции.
Неизвестная конфигурация, нет БД, квота, 401/429/5xx, timeout, отказ и неверный ответ
дают обычную сводку без поломки доставки PDF. Скачивание PDF не вызывает модель.

## Проверка

```
python -m pytest -q
python tools/evaluate_analysis.py --output evaluation.json
```

12 синтетических сценариев проверяют правила. Это не оценка precision/recall
на реальных людях и не проверка качества живой модели. Тесты интеграции OpenAI
используют MockTransport, фиктивный ключ и не отправляют запросы в интернет.
По умолчанию генеративные вызовы отключены и во всём наборе тестов.
