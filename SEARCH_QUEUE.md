# Постоянная очередь отчётов

При `SEARCH_QUEUE_ENABLED=true` веб-приложение одной транзакцией сохраняет заказ,
его владельца и зашифрованные параметры поиска в PostgreSQL. Задача остаётся
доступной после перезапуска. Временные данные заказа удаляются из БД при
завершении. Общая квота приёма составляет 20 заказов в час, до двух на email.
Повтор возвращает тот же ID, пока заказ активен и 10 минут после окончания.

## Запуск в тестовом окружении

Запустите веб-процесс `python server.py` и хотя бы один отдельный процесс
`python search_worker.py`. В обоих включите `SEARCH_QUEUE_ENABLED` и используйте
одну тестовую БД, одинаковые настройки аккаунтов, `ACCOUNT_SECRET` и
`ACCOUNT_REPORT_KEY`. Обработчику также нужны действующие для окружения настройки
источников и почты. Для нагрузки используйте автоматические тесты ниже. Платный
сервис или новая база в существующей конфигурации хостинга не создаются.

Несколько обработчиков забирают заказы через `FOR UPDATE SKIP LOCKED`.
После SIGTERM обработчик заканчивает текущую задачу и перестаёт брать новые.
При аварии незавершённый поиск возвращается к обработке по истечении 15 минут,
максимум три захвата. Заказы старше 24 часов без активного обработчика
завершаются ошибкой. После фиксации начала отправки почты повторная отправка
при аварии исключена, статус становится `delivery_unknown`. Он означает, что
письмо могло быть отправлено и подтверждения нет.

Общий лимит HTTP-запросов хранится в PostgreSQL отдельно по источникам.
Известные поддомены одного провайдера пользуются одним лимитом. Между выдачами
разрешений выдерживается 1,05 секунды на источник. При ожидании дольше трёх
секунд или недоступности БД запрос завершается ошибкой источника. Лимит действует
на поиски, мониторинг и служебную диагностику в процессах с включённым режимом.
Для нагрузочного теста реальных источников понадобятся отдельные согласованные
квоты. Этот тест их не проверяет.

## Нагрузочная проверка

`python -m pytest -q tests/test_search_queue.py` с локальной одноразовой
PostgreSQL и `ACCOUNTS_TEST_DATABASE_URL`, `PRIVETEK_TEST_ALLOW_RESET=1`,
`ACCOUNTS_NATIVE_POSTGRES_TESTS=1`. Используйте пустую тестовую БД.
Тест создаёт 1000 синтетических заказов через 12 параллельных соединений,
затем запускает восемь потоков обработчиков с отдельными транзакциями.
Поиск, генерация и почта имитируются. Тест проверяет число принятых и
завершённых заданий, отсутствие дублей и удаление параметров. Лимит приёма
повышается только внутри теста. Отдельный сценарий проверяет конкуренцию
16 запросов за разрешение одного источника.
