# PriveTek: подготовленная версия прототипа

Сервис принимает форму Tilda, проверяет email и телефон в подключённых источниках, формирует русскоязычный PDF и отправляет письмо с вложением через Brevo (или SMTP в альтернативной конфигурации).

## Что изменено

- Реализована отправка PDF через SMTP: STARTTLS или SSL, проверка сертификата, тайм-аут 30 секунд. Пароли находятся в окружении / `.env`.
- Шрифт ищется рядом с кодом, а не в папке запуска. Имена PDF содержат UUID; одновременные заявки не перезаписывают друг друга.
- Email обязателен. Имя и телефон необязательны. Если телефон заполнен, нужен международный формат с `+`; проверяются код страны и возможная длина, но не принадлежность номера человеку.
- Некорректные формы возвращают ошибку; при отсутствии настроек почты заявки не принимаются.
- Не более четырёх одновременно выполняемых заявок на процесс; новые получают 503, если все места заняты.
- Убрана печать персональных данных и текста исключений в журналы приложения. Ошибки содержат идентификатор задания и этап.
- Исправлено подключение HIBP: вместо несовместимого импорта используется официальный API v3. Ключ необязателен для запуска, но необходим для проверки утечек: https://haveibeenpwned.com/API/v3 . Без ключа в PDF будет предупреждение.
- Код страны отделяется от номера. Подключены консервативные проверки Instagram, Amazon и Spotify; отдельно проверяется публичный аватар Gravatar. Доступность источников не гарантируется.
- Ошибки и ограничения источников больше не скрываются как успешная проверка без находок.

## Бесплатное размещение: Render + Brevo

Для текущего варианта используйте `MAIL_PROVIDER=brevo`. Отправка PDF идёт через HTTPS API Brevo: бесплатный Render блокирует стандартные SMTP-порты. SMTP сохранён как альтернативный режим.

Почта команды: **privetekmail@gmail.com**. Это адрес отправителя и ответов, но его нужно подтвердить в Brevo. Пароль Gmail приложению не нужен.

1. Зарегистрируйтесь в Brevo на почту команды и подтвердите её. Выберите бесплатный тариф. В настройках отправителей добавьте имя `PriveTek` и адрес `privetekmail@gmail.com`, подтвердите кодом из письма. При необходимости завершите проверку аккаунта для транзакционных писем. Бесплатный почтовый домен может быть заменён Brevo своим доменом при отправке.
2. Создайте **API key**, а не SMTP key. Сохраните его в менеджере паролей. Не публикуйте ключ в чате, GitHub или архиве.
3. Создайте аккаунт Render. Для удобного подключения разместите содержимое этой папки в приватном репозитории команды на GitHub. Файл `render.yaml` должен быть в корне репозитория; `.env` и `reports/` загружать нельзя.
4. В Render создайте Blueprint из репозитория. В комплекте `render.yaml` с тарифом `free`; перед подтверждением проверьте, что выбран именно Free и нет платных ресурсов. Введите ключ в секретную переменную `BREVO_API_KEY`.
5. `MAIL_PROVIDER=brevo`, `MAIL_FROM=privetekmail@gmail.com` и `HOST=0.0.0.0` уже указаны в конфигурации. Порт выдаёт Render. При необходимости добавьте `HIBP_API_KEY`; без него проверка утечек не выполняется.
6. После размещения проверьте главную страницу HTTPS-адреса: она должна ответить `ok`. Затем отдельно проверьте письмо с демо-PDF и подключите форму Tilda.

Сервис размещён на https://privetek.onrender.com/. Деплой версии Spotify подтверждён 4 октября 2026. Автотесты текущих изменений выполнены локально на Python 3.9.6; прохождение тестов не подтверждает реальную доставку писем.

**Ограничения Free:** сервер засыпает при отсутствии входящих запросов, первый запрос может ждать запуска. Файлы PDF находятся на временном диске и теряются при перезапуске/переразвёртывании; постоянный диск в бесплатную конфигурацию не входит. Фоновые задачи не имеют постоянной очереди. Для демонстрации заранее откройте главную страницу и дождитесь `ok`, затем отправляйте форму. Реальную совместимость с проверочным запросом и повторами Tilda нужно проверить на аккаунте команды.

Источники: [Render Free](https://render.com/docs/free), [Render Blueprint](https://render.com/docs/blueprint-spec), [Brevo API](https://developers.brevo.com/reference/send-transac-email).

## Быстрый запуск

Команды выполняются из папки, где находится этот README. Нужен Python с поддержкой зависимостей (код проверен на Python 3.9.6/macOS; другие версии и Linux ещё не проверялись). Для размещения на сервере используйте поддерживаемую версию Python и повторите тесты в выбранной среде.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
cp .env.example .env
```

В Windows активация: `.venv\Scripts\activate`.

### Посмотреть PDF без почты, Tilda и реальных поисков

```sh
python demo_report.py
```

Путь к готовому файлу появится в терминале. Результат сохраняется в `reports/`. На нём явно указано, что данные вымышлены. Пример готового отчёта приложен к передаваемому архиву как `demo-report.pdf`.

### Настроить почту

Для Brevo заполните в `.env` `BREVO_API_KEY`, оставьте `MAIL_PROVIDER=brevo` и `MAIL_FROM=privetekmail@gmail.com`. Для альтернативного SMTP-режима задайте `MAIL_PROVIDER=smtp` и заполните:

| Поле | Что указать |
| --- | --- |
| SMTP_HOST | Адрес SMTP-сервера почтового провайдера |
| SMTP_PORT | Обычно 587 для STARTTLS или 465 для SSL; подтвердите у провайдера |
| SMTP_SECURITY | `starttls` или `ssl` |
| SMTP_USERNAME | Логин отправителя |
| SMTP_PASSWORD | SMTP-пароль или пароль приложения, выданный провайдером |
| SMTP_FROM | Подтверждённый адрес отправителя без отображаемого имени |
| HIBP_API_KEY | Ключ API HIBP, если он есть |

`.env` уже исключён из Git. Не пересылайте его в чат или вместе с архивом. Настройки окружения хостинга имеют приоритет над `.env`. Обычный пароль ящика подходит не всем провайдерам; если требуется OAuth, текущий SMTP-модуль его не поддерживает.

После настройки можно отправить демонстрационный отчёт **на собственный тестовый адрес**. Эта команда действительно отправляет письмо; замените адрес и путь вручную:

```sh
python -c "from dotenv import load_dotenv; load_dotenv(); from email_sender import send_report; print(send_report('YOUR_OWN_EMAIL', 'demo-report.pdf'))"
```

Успешный результат означает, что SMTP-сервер принял письмо, но не гарантирует его попадания во «Входящие». Проверьте сам ящик, спам и состояние отправителя у провайдера. Автоматических повторов после неоднозначного сбоя нет, чтобы не создавать дубли писем.

### Запустить обработчик формы

```sh
python server.py
```

Откройте `http://127.0.0.1:8000/`: ответ `ok` подтверждает запуск HTTP-сервера, но не проверяет SMTP и источники поиска. По умолчанию доступ открыт только с этого компьютера.

## Подключение Tilda и постоянного сервера

1. Разместите папку приложения на сервере с Python. Установите зависимости, задайте переменные окружения и учтите хранение папки `reports/`: на бесплатном Render постоянного диска нет.
2. Запустите `python server.py` как сервис с автоматическим перезапуском. В конфигурации контейнера при необходимости задайте `HOST=0.0.0.0`; не открывайте незащищённый порт приложения напрямую в интернет.
3. Настройте постоянный HTTPS-адрес через хостинг / обратный прокси. Приложение само не выдаёт TLS-сертификат. Ограничьте размер тела запроса и частоту заявок на уровне прокси.
4. В настройках формы Tilda укажите HTTPS-адрес обработчика `/`. Поля: `Email` (обязательно), `Phone`, `Name`. Нужны именно эти имена переменных, с указанным регистром. Для телефона задайте международный формат с `+`.
5. Отправьте одну заявку со своими данными и проверьте PDF и доставку письма. Сверьте проверочный запрос, повторные отправки и настройки формы с фактическим проектом команды.

Tilda подключалась к Render, доставка PDF была подтверждена пользователем в сентябре. Повторная сквозная проверка 4 октября пока не завершена: письмо не получено. Ngrok не используется.

## Проверки для разработчика

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m pip check
```

Автоматические тесты проверяют PDF с кириллицей и длинными данными, параллельную генерацию, SSL/STARTTLS и байты PDF-вложения, ошибки SMTP, валидацию формы, перегрузку, освобождение рабочих мест после ошибок, код страны телефона и HIBP на имитированном ответе. Тесты не отправляют письма и не ищут реальные персональные данные.

`requirements.txt` закрепляет прямые зависимости. `requirements-dev.txt` добавляет тестовые библиотеки. `tested-environment.txt` фиксирует версии установленного окружения для диагностики; это не гарантия совместимости с другой ОС.

## Что остаётся ограничением прототипа

- Задания выполняются в памяти процесса, без постоянной очереди. При аварийном перезапуске они теряются; используйте один процесс приложения. Нет истории заданий и интерфейса статусов. Подавление дублей и квоты действуют только в одном процессе и сбрасываются при перезапуске.
- HTTP `ok` означает приём заявки, а не завершение поиска или доставку письма. Ошибки фоновой обработки фиксируются в журнале по `job=...`; PDF после сбоя почты остаётся на диске для ручной повторной отправки.
- Нет аутентификации вебхука и подтверждения владения email. Добавлены базовые квоты; это не полная защита от злоупотребления почтовой отправкой. Перед открытым запуском нужно согласовать с командой защиту формы/обработчика и ограничения на уровне инфраструктуры. Ограничение четырёх задач не заменяет такую защиту.
- PDF сохраняются в `reports/` без автоматического удаления. Команде нужно установить срок хранения и ограничить доступ к этой папке; не публикуйте её как статические файлы сайта.
- Доставка PDF ранее подтверждалась пользователем; текущая сквозная проверка ещё не завершена. Spotify совпал с двумя контрольными аккаунтами при локальной проверке. Instagram и Amazon могут блокировать запросы, HIBP требует ключ подписки. Доступность источников, блокировки и лимиты могут влиять на результат; наличие/отсутствие регистрации не является доказательством личности.
- Исходный сайт Tilda и его настройки в эту папку не входят.

## Подавление повторов и квоты (4 октября 2026)

После проверки полей заявки сервер сравнивает нормализованные email и телефон.
Одинаковые заявки получают один X-Request-ID и не запускают повторный поиск или письмо,
пока задача выполняется и ещё 10 минут после её завершения (включая ошибку).
Повторный ответ содержит X-Duplicate: true. Изменение имени не создаёт новую задачу.

Лимиты: 2 новые заявки на email в час, 20 новых заявок на процесс в час,
4 одновременно выполняемые задачи. Превышение квоты возвращает HTTP 429 и Retry-After;
занятые места или невозможность запустить поток возвращают 503 и не расходуют квоту.
Тело формы ограничено 16 КиБ, загрузка файлов запрещена. Проверочный test=test не расходует квоту.
Идентификаторы для квот хешируются с временным секретом; исходные email не хранятся в счётчиках.

Нужен один процесс сервера. После перезапуска защита от повторов начинается заново.
Постоянная очередь, распределённые квоты и подтверждение адреса остаются отдельными задачами.
Не обещайте пользователям гарантированную доставку на основании одного HTTP 200.

## Gravatar и передача данных

Gravatar получает SHA-256 от email без пробелов по краям и в нижнем регистре.
Это псевдонимизация, а не анонимизация: хеш может быть сопоставлен с известным email.
Запрос HEAD на официальный адрес аватара использует d=404, не загружает само изображение,
не создаёт аккаунтов и не отправляет писем. HTTP 200 с типом изображения — публичный аватар;
404 — аватар с рейтингом по умолчанию не найден; остальные ответы — недоступная проверка.
Ни один из этих ответов не подтверждает личность владельца или отсутствие аккаунта.
На сайте следует перечислить сторонние источники и пояснить передачу email/его хеша.
Документация: https://docs.gravatar.com/sdk/images/ .

## Организация отчёта (9 октября 2026)

Отчёт группируется по виду проверки (аватары, утечки, email, телефон), внутри раздела сначала показываются находки и возможные совпадения, затем проверки без находок и ограничения. Для известных источников указан официальный сайт, без идентификаторов пользователя в URL. Время завершения проверки записывается в UTC; дата формирования PDF не подменяет время проверки. У пропущенных проверок времени выполнения нет. Дата утечки обозначена отдельно.

Точные дубли записей checks/email_breach удаляются без изменения исходных данных; порядок категорий утёкших данных не влияет на сравнение. Разные статусы, даты и доказательства сохраняются отдельно. Итоговые счётчики используют те же очищенные записи. Это не объединение личностей и не автоматический поиск связанных людей.

Демо без сети и почты: `python demo_grouped_report.py`. В нём явно отмечены вымышленные результаты. Проверено 80 автоматических тестов. Изменения этой итерации подготовлены локально; публикация в GitHub/Render не подтверждена.
