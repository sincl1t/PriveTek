# Этап 3 — Account discovery, первая версия

Согласованный объём: небольшой проверенный набор из трёх сайтов, а не поиск во
всех соцсетях. Поддерживаются Roblox, Scratch и Codewars. Ввод — точный username;
результат — публичный профиль, распознанное отсутствие, недоступность или пропуск.
Это дополнение к 11 площадкам этапа 2. Email/телефон не преобразуются в username.

## Методы

| Сайт | Метод и основание | Ссылка |
|---|---|---|
| Roblox | Публичное разрешение username → числовой ID; ссылка на динамический профиль строится по ID, не по displayName | https://create.roblox.com/docs/cloud/reference/domains/users |
| Scratch | Публичный REST lookup; ID и точный username | https://github.com/scratchfoundation/scratch-rest-api/wiki/Users |
| Codewars | Публичный Users API; ID и точный username | https://dev.codewars.com/ |

У Roblox POST `/v1/usernames/users` — операция чтения, без авторизации,
создания аккаунта или отправки сообщения. Никакие формы регистрации/восстановления
не вызываются. Для этих сайтов подходящий публичный метод позволяет обойтись без
разбора страницы и запуска браузера. Браузерная автоматизация, вход в чужие
аккаунты, CAPTCHA, прокси и поиск по displayName в эту версию не входят.

npm и PyPI исследованы, но не включены: npm вернул 403, PyPI на отрицательный
контроль — страницу проверки HTTP 200. Такие ответы не считаются отсутствием.
Работа сайтов с обязательным интерактивным браузером остаётся отдельным расширением.

## Критерии приёмки первой версии

1. Все три источника подключены к реальному поиску и единому результату/PDF.
2. По два известных публичных профиля и два синтетических отрицательных примера
   на каждом сайте; два повторения, 24 результата с ожидаемым статусом.
3. В production с Render положительный и отрицательный контроль каждого сайта
   дают found/not_found. Проверка выполняется один раз при старте, отдельно от
   готовности сервиса; результат фиксируется в логе `discovery_probe` и доступен
   команде в `GET /api/sources` под полем discovery_probe. Это снимок на момент
   проверки; проверка не гарантирует постоянную доступность источников.
4. Тестами проверены чужие имена, некорректные ID/JSON, HTML, 403/429/503,
   redirects, лимиты, размер ответа, интеграция поиска и ссылки в PDF.
5. Недоступность не маскируется под отсутствие, совпадающее имя не доказывает
   принадлежность человеку. Результат не содержит bio, фото, displayName и полных
   ответов API; логи диагностики не содержат пользовательских идентификаторов.

## Эксплуатация

Фиксированный список адресов, HTTPS, без redirects и повторов. На источник не
более одного запроса в секунду в одном процессе. При 429 пауза минимум 60 секунд,
числовой Retry-After учитывается до часа. Занятый лимит даёт unavailable, не
ложный отрицательный ответ. Размер JSON до 256 KiB, общий таймаут одного lookup
15 секунд, сетевой таймаут 12 секунд. Дополнительные процессы/реплики потребуют
общего лимитера. Новые env-переменные, зависимости и изменения схемы БД не нужны.

Запуск контролей из корня репозитория (только фиксированные публичные примеры):

```
python tools/verify_discovery.py --output discovery-verification.json
```

Качество на этих примерах не равно precision/recall поиска по населению: набор
мал, отрицательные примеры синтетические, независимая разметка отсутствует.
Для следующего расширения нужны новые площадки и собственные/согласованные
тестовые аккаунты. Текущую версию можно закрыть только после выполнения критериев,
а не по количеству написанных адаптеров.
