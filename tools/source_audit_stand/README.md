# Стенд аудита источников PriveTek

Стенд запускает личный кабинет PriveTek и проводит заявку через рабочие адаптеры, карточку находок и PDF. В ручном режиме доступны живые проверки LeakCheck по email, GitHub и GitLab по username и Amazon по телефону. Автопрогон проверяет LeakCheck, GitHub и GitLab. Ответы этих источников приходят из интернета. Подтверждение тестовых аккаунтов и отправка отчётов используют почтовый имитатор в памяти, поэтому статус «Письмо принято сервисом» означает приём имитатором.

Команды выполняются из корня репозитория. Нужны Docker Engine в режиме Linux-контейнеров, Docker Compose v2 и доступ к проверяемым источникам. Приложение и PostgreSQL 18 запускаются в контейнерах. При сборке образа устанавливаются зависимости приложения.

## Ручной запуск

```sh
docker compose -f tools/source_audit_stand/compose.yaml up --build
```

Дождитесь сообщения **«СТЕНД АУДИТА ИСТОЧНИКОВ ГОТОВ»** и откройте <https://127.0.0.1:8443/account/login>. Используйте адрес `127.0.0.1` и подтвердите переход к локальному сайту с самоподписанным сертификатом.

Стенд создаёт и подтверждает два аккаунта. Пароль для обоих — `PriveTek-Audit-2026!`.

| Вход в кабинет | Ожидаемый статус LeakCheck |
| --- | --- |
| `example@example.com` | `found` |
| `stage2-health-pvtkz8q4n2x7r9@example.com` | `not_found` |

LeakCheck проверяет email текущего аккаунта в каждой заявке. Из контейнера в LeakCheck отправляется префикс SHA-256 нормализованного адреса. Транспорт пропускает только хеши двух адресов из таблицы. Чтобы проверить только LeakCheck, оставьте username и телефон пустыми. Остальные email-источники и прочие проверки профилей на стенде внешних запросов не выполняют.

### Ручная проверка профилей

Откройте «Новая проверка», укажите от одного до трёх username без ссылок, оставьте телефон пустым, подтвердите согласие и запустите заявку. Каждый username проверяется и на GitHub, и на GitLab. Проверьте статусы источников и ссылки в карточке и скачанном PDF.

| Что ввести | Что проверить |
| --- | --- |
| `octocat` и `sytses` | GitHub находит `octocat`, GitLab находит `sytses`. Ссылки ведут на совпавшие профили |
| `pvtkz8q4n2x7r9` | Оба источника возвращают `not_found` при распознанном отрицательном ответе |
| `Octocat` и `Sytses` | Совпадения принимаются без учёта регистра, ссылки используют канонический username из ответа |

Перекрёстные сочетания тоже дают живые результаты. Подтверждение принадлежности профиля остаётся за пользователем. Для проверки профилей с более коротким PDF используйте аккаунт с ожидаемым `not_found` в LeakCheck.

### Живая проверка Amazon по телефону

В форме «Новая проверка» введите номер с кодом страны в поле «Телефон». Чтобы исключить запросы к GitHub и GitLab, оставьте username пустым. LeakCheck по email аккаунта выполнится в той же заявке. После завершения сравните `Amazon · телефон` в покрытии источников с разделом «Регистрации телефона на сайтах» в PDF.

Адаптер открывает страницу входа Amazon и передаёт номер только через распознанную форму. Поле пароля после отправки номера даёт `possible` — «Возможная регистрация». CAPTCHA, лимит или нераспознанный ответ дают `unavailable` — «Проверка недоступна». Метка `phone="submitted"` в логе обозначает телефонную проверку. Факт отправки номера можно определить по запросу `POST`. При CAPTCHA на первом экране в логе будет только запрос страницы входа.

Лимит составляет две новые заявки на email за час. Повтор с теми же параметрами использует существующую заявку, пока она выполняется и в течение десяти минут после её завершения.

## Автоматический прогон с живыми запросами

```sh
docker compose -p privetek-source-audit-verify -f tools/source_audit_stand/compose.yaml -f tools/source_audit_stand/compose.verify.yaml up --build --attach app --no-log-prefix --exit-code-from app
```

Файл `compose.verify.yaml` передаёт приложению `--verify` и убирает публикацию порта. Автопрогон работает в отдельном Compose-проекте и сам отправляет заявки через API кабинета.

| Сценарий | Email из подготовленного аккаунта | Username |
| --- | --- | --- |
| `known` | Положительный контроль LeakCheck | `octocat`, `sytses` |
| `absent` | Отрицательный контроль LeakCheck | `pvtkz8q4n2x7r9` |
| `case` | Отрицательный контроль LeakCheck | `Octocat`, `Sytses` |

Скрипт сверяет статусы источников, подписи в PDF и ссылки на ожидаемые профили в карточке и PDF. Он также проверяет, что приложение оставляет принадлежность находок неподтверждённой. При полном прогоне выполняются три запроса к LeakCheck и десять запросов к GitHub и GitLab суммарно.

В консоли у каждого сценария свой заголовок. После сценариев выводится блок **«Итоги автоматической проверки»** со статусами источников, именами PDF и расхождениями. Если проверки дали расхождение, скрипт продолжает прогон. Если сценарий прервался ошибкой выполнения, оставшиеся отмечаются как «Не запущен». Код завершения ненулевой при ошибке или расхождении. После выхода приложения Compose останавливает PostgreSQL этого проекта.

Файлы сохраняются в `tools/source_audit_stand/artifacts/`.

- `verification.txt` — итоговая сводка без журнала.
- `verification.json` — результаты сценариев и отдельных проверок.
- `sources-known.pdf`, `sources-absent.pdf`, `sources-case.pdf` — PDF, скачанные скриптом после обработки заявок.

Последующий прогон перезаписывает файлы с теми же именами по мере их создания. После прерванного прогона в каталоге могут остаться файлы предыдущего запуска. Если итоговая сводка сформирована, в `verification.json` указаны время её создания и PDF текущих сценариев.

## Как читать журнал

В ручном режиме журнал виден в терминале запуска. Чтобы открыть его из другого терминала, выполните команду.

```sh
docker compose -f tools/source_audit_stand/compose.yaml logs -f --tail 50 app
```

`TRACE` показывает этапы заявки от приёма и поиска до генерации PDF, сохранения и имитации отправки. Строки `AUDIT` связываются по идентификатору `job`, имени источника и значению, которое проверяется.

1. **ЗАПРОС** — метод и адрес запроса. Для GitHub и GitLab виден username, для LeakCheck — контрольный email в журнале и хеш в URL, для Amazon — только разрешённый путь.
2. **ОТВЕТ** — HTTP-статус, время и выбранные поля. LeakCheck показывает `found` отдельно от числа источников, а также категории и первые три источника. Для Amazon журнал показывает тип и размер ответа без HTML. При сетевом сбое выводится тип ошибки.
3. **ОБРАБОТКА ПРИЛОЖЕНИЕМ** — статус и пояснение адаптера, сведения о находке профиля или регистрации либо число источников LeakCheck, переданных в отчёт.
4. **В ОТЧЁТЕ — ПРОЧИТАНО ИЗ PDF** — подпись, раздел и пояснение, извлечённые из PDF. Поле `соответствует_результату_обработки` показывает результат сверки. Если журнал не может сопоставить строку с PDF, он сообщает об этом отдельно.

Номер телефона, параметры и тело запроса Amazon в `AUDIT` не выводятся. Полные ответы источников, коды входа и содержимое имитируемых писем в журнал этапов заявки не включаются.

## Локальные тесты стенда

Тесты проверяют маршрутизацию, содержание журнала, сверку с текстом PDF и формат автосводки. Внешние ответы в тестах подставляются локально.

```sh
docker compose -f tools/source_audit_stand/compose.yaml run --build --rm --no-deps -T --entrypoint python app -m unittest discover -s tools/source_audit_stand -p 'test_*.py'
```

Имитационные сценарии из отчёта аудита вынесены в [tests/test_source_quality_audit.py](../../tests/test_source_quality_audit.py).

## Остановка и хранение данных

В ручном режиме нажмите `Ctrl+C`, чтобы остановить контейнеры. Для удаления контейнеров и сети ручного стенда выполните команду.

```sh
docker compose -f tools/source_audit_stand/compose.yaml down
```

Для удаления остановленных контейнеров и сети автопрогона выполните отдельную команду.

```sh
docker compose -p privetek-source-audit-verify -f tools/source_audit_stand/compose.yaml -f tools/source_audit_stand/compose.verify.yaml down
```

При следующем запуске приложение создаёт новую временную БД с тестовыми аккаунтами. Заявки, сессии и отметки прошлого запуска теряются. Скачанные вручную PDF и файлы в `tools/source_audit_stand/artifacts/` остаются на устройстве.
